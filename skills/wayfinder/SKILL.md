# wayfinder：给大事画地图

一件事大到一个会话装不下，而且从这里到终点的路还看不清时用。先不动手，先找路：在票务系统上建一张**地图**，把要做的决定拆成**票**，一次解决一张。

## 原则

- 只规划不动手：每张票的产出是一个决定，不是交付物。想直接动手了，通常说明走到了地图边缘，该交出去了（地图 Notes 里另有约定的除外）
- 一次只问一个问题：讨论都走 grill-wide，不一轮抛一串问题
- 新信息来了先改票：新需求、会议结论先加票或更新票，再拿着票讨论；不另写方案长文
- 纪要、需求里出现的具体写法默认是示例，不是定好的方案；先开 research 票查成熟产品怎么做
- 给人看的地方用票的标题称呼票，不用光秃秃的编号

## 地图和票

存在哪、怎么查前沿、怎么认领，看 `docs/agents/issue-tracker.md` 的「Wayfinding operations」一节；没有这份文档，先问用户票放在哪。

**地图**是一张带 `wayfinder:map` 标签的票，是索引不是仓库：每个决定只写在它自己的票里，地图只放一行要点和链接。正文五节，**标题保持英文原样**（看板按标题解析）：

```markdown
## Destination
<终点：这张地图要走到的 spec、决定或改动，一两行>

## Notes
<领域；每次会话都要用的 skill；这件事的长期约定>

## Decisions so far
- [<已关票的标题>](链接)：<一行要点>

## Not yet specified
<还说不准、暂时拆不成票的问题>

## Out of scope
<明确不做的：一行一条，写理由，链接已关的票>
```

**票**是地图的子票，正文只写 `## Question`，大小控制在一个会话能解决。

- 标签只用 `wayfinder:research|prototype|grilling|task`，不加分诊标签
- 字段行（`Status:` `Type:` `Blocked by:` `Labels:`）顶格、不加粗、只写单个值；没有阻塞写 `Blocked by: —`，不留空。看板读不出加粗的字段，空值会吞掉下一行
- 动手前先认领，别的会话就会跳过它
- 阻塞关系用票务系统自带的依赖；阻塞它的票全关了才算解锁。**前沿** = 打开、已解锁、没人认领的票
- 答案在解决时记录，不写进问题正文；过程中产出的东西放链接，不贴全文

## 票的四种类型

| 类型 | 谁做 | 怎么解决 |
|---|---|---|
| research | agent 自己 | 子 agent 调 research 查资料，结论放在 `research/<名>` 分支上（推送，不开 PR），票里放指针 |
| prototype | 和用户一起 | 调 prototype 做个粗糙的东西让用户看了再定 |
| grilling | 和用户一起 | 默认类型。调 grill-wide 和 domain-modeling |
| task | 能自己做就自己做，否则给用户一张清单 | 做决定之前必须先完成的手工活；答案里记下做了什么、后面的票要用的事实 |

和用户一起的票只能在真实对话里解决，agent 不能替用户回答。

本文的 grill-wide 指 `arnold-skills:grill-wide`，调 Skill 工具时写全名。

grill-wide 用在一张票上时：底片 = 地图 + 这张票 + 相关的已关票；决定表写进这张票的答案；第 6–7 步（还原、收件人 review）留到终点再做。

## 迷雾和不做的

- 问题已经能说准 → 开票，哪怕暂时被阻塞；还说不准 → 写进 Not yet specified，不提前切成票
- 解决一张票后，看清了的迷雾转成新票，并从 Not yet specified 删掉
- 超出终点的不是迷雾，是不做：已有的票关掉，在 Out of scope 记一行理由；不进 Decisions so far

## 两种用法

每个会话只解决一张票，research 票除外。

### 画地图：用户带着一个模糊的想法来

1. 定终点：用 grill-wide 和 domain-modeling 讨论清楚终点是什么（spec、决定还是改动）
2. 铺前沿：跑 grill-wide 的阶段 0–2（收底片、铺分支、合并排序）。A、B 级的分支开票，B 级可以几条合成一张；C 级不开票，实现时再定；还说不准的进 Not yet specified。铺完发现路已经清楚、一个会话就能做完，就不需要地图，停下来问用户怎么办
3. 建地图：填好 Destination 和 Notes，Decisions so far 留空
4. 建票：先把能说准的票都建出来，第二遍再连阻塞关系和互相引用。票要先有编号才能互相引用，不写占位编号
5. 派子 agent 并行解决 research 票。结果攒齐后合成一条汇报，只报和用户当前问题有关的，不逐条转述
6. 停。画地图本身就是一个会话的工作，不解决任何票

### 走地图：用户带着地图来，可以不指定票

1. 读地图，不读所有票的正文
2. 选票：用户指定了就用那张，否则取前沿里排第一的；动手前先认领
3. 按票的类型标签解决（看标签，不看正文）；需要时再读相关票或已关票的全文
4. 记录：答案写进票，关票，在 Decisions so far 加一行
5. 更新地图：新冒出的票先建再连；看清了的迷雾转成票；超出终点的移进 Out of scope
6. 这个决定推翻了以前的说法时：在地图、所有票和已有产物里 grep 旧说法，全部清掉再给用户看

用户可能同时在别的会话里推进其他票，票务系统随时会被改动。

## 到终点

终点是 spec 时，最后用 grill-wide 第 6–7 步写 spec 并做收件人 review，然后交给 to-tickets 拆票。
