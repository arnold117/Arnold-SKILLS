# implement：按票写代码

## 开始前

- 用户给的是票的引用：先从票务系统取出来，报一下票的标题再动手；引用有歧义就问
- 先 fetch，从最新的开发主线开分支（主线和分支规则按仓库约定）；不在主线上直接改
- 先读这张票要碰的代码现状，再动手

## 做

- 先实现，不写先行测试
- 改的过程中常跑类型检查和相关的单个测试文件；现有测试、回归闸、契约测试、红线扫描照跑照用
- 实现完调 `arnold-skills:lean-verify` 补最少的测试，按它的格式列表：每个测试防什么 bug
- 跑全量测试。红了先和主线对比：主线上本来就红的不算这次的，这次引入的要修

## 收尾

- 调 `mattpocock-skills:code-review` 审本次改动，修完再跑一次全量
- 提交到当前分支。推不推、怎么合入等用户定；推的话走 PR，不直推主线，也不推半成品
- 报告带前后对比：测试数、代码行数，涨了就说涨了，说明原因
