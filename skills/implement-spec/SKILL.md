# implement-spec：整批实现一份 spec

输入：一份 spec（grill-wide 第 6 步的产出）和 to-tickets 拆好的票。票放在哪、怎么关，看 `docs/agents/issue-tracker.md`。

票不是步骤清单，是一张带阻塞关系的图：任何时候都有一批可以开工的票，叫**前沿**。

## 分工

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 父会话 | 读全貌、派工、写 brief、合入、跑全量、解冲突、登记、收尾 review | 不把判断类的活下放 |
| 实施子 agent | 在自己的 worktree 里改代码和测试 | 不碰主工作树、不推送、不碰票和地图、不碰共享登记文件 |

- 每次派子 agent 都显式写 `model: sonnet`，不派 Opus；汇报里写明派的是什么模型
- 子 agent 交回来的东西要复核，不直接信

## 步骤

1. 读 spec 和所有票，理清阻塞关系
2. 可选：派一个只读子 agent 去看票要碰的代码或外部文档，笔记写到仓库外的目录，后面的子 agent 都能读
3. 先 fetch，从最新主线开集成分支和它的 worktree。分支起有意义的名字（如 `wt/<功能>`、`wt/<功能>-t<N>`），不用工具自动生成的
4. 派工看**改动的文件相不相交**，不看票号：不相交的票马上并行开；相交的等前一张合入后，从最新的集成分支再开。一张票一个 worktree、一个子 agent
5. 子 agent 的 brief 固定写明：
   - 先确认 worktree 基于集成分支；工具开的 worktree 默认从主线分出，不是的话先 `git merge --ff-only <集成分支>`
   - 只在自己的 worktree 里改，不推送，不碰票、地图和共享登记文件
   - 先实现，再调 `arnold-skills:lean-verify`；改动前后各跑一次全量，报数
   - 前一张票刚改过的文件（有的话）先 `git log -N --stat` 看一眼
   - 测试替身的名字不能和真实的策略、函数撞名
6. 合入只由父会话做：rebase 到集成分支 → 跑这张票的目标测试 → `merge --ff-only` → 跑全量 → 删 worktree 和分支。两个分支各自全绿，不代表合并后测试还在测东西，所以每次合入都跑全量。冲突一般只出在文档里：每一行取改它的那张票的版本，不手工糊
7. 合入后前沿变了，就接着派新的子 agent
8. 全部合入后：集成分支跑全量（和主线对比，主线上本来就红的不算）→ 调 `mattpocock-skills:code-review` → 派一个子 agent 修 review 报的问题 → 父会话自己再跑一次全量
9. 父会话统一回填票的状态和答案、地图、登记文件、记忆。先看仓库约定（.gitignore、哪些文件不提交）再决定入不入库
10. 汇报：每一波派了几个子 agent、什么模型；前后对比表（测试数、代码行数；冗余和体量分开列，涨了就说涨了）。推不推、怎么合入等用户定；推的话走 PR，不直推主线
11. 清理所有 worktree

坑：几个 worktree 并行跑全量时，共用的临时目录会偶尔互相踩出假红，单独重跑一遍确认。
